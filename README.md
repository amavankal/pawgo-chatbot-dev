# PawGo scraping proof of concept

This project is a proof of concept for collecting dog-care information for PawGo. It fetches webpages, extracts article content, keeps article sections, cleans obvious page boilerplate, splits the text into searchable chunks, creates embeddings with Qwen3 Embedding through Ollama, and stores the vectors and source metadata in Qdrant.

The scraper can be run by itself with `node scrape.js`. To run the full pipeline, use the complete sequence below.

## Install the project libraries

Install Node.js 18 or newer. In Terminal, go to this project folder and run:

```sh
npm install
```

## Set up local Qdrant

Each teammate runs their own local Qdrant database. Install and start [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/). Then, for a new setup, start Qdrant in Docker with:

<span style="color: gray; font-style: italic"> _An alternative to installing Docker Desktop to get the Docker Engine w/ a Linux VM is to install `colima`, which provides the Linux environment Docker needs to run. You would then also need to install the Docker CLI client `docker` and `docker-compose` separately if you want to use colima. Start the Docker runtime with `colima start`_</span>

### Shortcut

To start the Qdrant database container (in root of this project):

```sh
docker compose up -d
```

To stop the Qdrant database container (in root of this project). Pass `-v` to `docker compose down` if for some reason you don't want to save the vectors stored in the database for the next time you spin up the database:

```sh
docker compose down # if you want to remove the container (saves the database data)
docker compose stop qdrant  # if you want to temporarily stop qdrant; restart w/ docker compose start qdrant
```

### Using docker CLI with runtime args instead of docker compose

```sh
docker run -d \
  --name pawgo-qdrant-db \
  --restart unless-stopped \
  -p 127.0.0.1:6333:6333 \
  -p 127.0.0.1:6334:6334 \
  -v pawgo_qdrant_storage:/qdrant/storage \
  qdrant/qdrant
```

The named Docker volume keeps the database files if the container is stopped. If a container named `pawgo-qdrant-db` already exists, start it from Docker Desktop or use `docker start pawgo-qdrant-db` instead of creating another one.

Check that Qdrant is responding:

```sh
curl http://127.0.0.1:6333
```

Open [http://localhost:6333/dashboard](http://localhost:6333/dashboard) to browse collections and points. Qdrant uses port `6333` for its HTTP API and dashboard and port `6334` for its gRPC API. The Docker command binds these ports to this computer for local development.

## Set up Ollama and the embedding model

Download and install [Ollama for macOS](https://ollama.com/download)*, then open the Ollama app so its local service is running. Download Qwen3 Embedding 4B:

<span style="color: gray; font-style: italic"> *An alternative to installing the Ollama app is to install just the CLI tool (`brew install ollama` on MacOS) and starting the local service (the server) with `ollama serve`</span>

```sh
ollama pull qwen3-embedding:4b
```

You can confirm the model is installed with:

```sh
ollama list
```

The embedding model is downloaded to each teammate's computer by Ollama. It is not stored in this GitHub repository. The scripts connect to Ollama at `http://127.0.0.1:11434`.

## Run the scraping and data pipeline

### Shortcut

This runs all the scripts in order and may take a couple minutes:

```sh
npm run ingest
```

### Step-by-step

To scrape the source URLs, run:

```sh
node ingest/scrape.js
```

To continue through cleaning, chunking, embedding, and database ingestion, run each script in order:

```sh
node ingest/clean.js
node ingest/chunk.js
node ingest/embed.js
node ingest/load-qdrant.js
```

The scripts create these files under `output/`:

- `OUTPUT.json` contains the article title, URL, and ordered content blocks such as headings, paragraphs, list items, and quotations.
- `FETCHED_HTML/` contains fetched webpage HTML for debugging when `DEBUG` is enabled in `scrape.js`.
- `cleaned_articles.json` contains the article blocks after whitespace normalization and exact boilerplate-label filtering.
- `cleaned_chunks.json` contains section-aware text chunks with source metadata.
- `embedded_chunks.json` contains the chunks and the embedding vectors generated by Ollama.

You can stop after `node chunk.js` to inspect the text and metadata before creating vectors or loading anything into Qdrant. In the Qdrant dashboard, look for the `pawgo_dogcare` collection to view loaded data.

The project includes some files from `output/` so teammates can see examples of the results. Generated outputs normally should not be committed for every run. If you are viewing `OUTPUT.json` in GitHub, use the **Raw** button to see the JSON more easily.

## How the scraper works

The scraper uses `fetch()` to download each webpage and JSDOM to convert its HTML into a DOM object. Mozilla Readability parses that DOM and selects what it considers the article content. The code then extracts headings and text blocks in their page order so the later steps can preserve sectioning.

The `prettier` library is used to format fetched HTML when the `DEBUG` option is enabled. This makes saved files in `FETCHED_HTML/` easier to inspect; it does not decide which content is relevant to PawGo.

The `clean.js` step normalizes whitespace and skips a short list of exact boilerplate labels such as “Skip to content.” It preserves the article wording. The `chunk.js` step groups text by section, targets 300 words per chunk, and attaches source details from `source_metadata.json`.

`source_metadata.json` records information from the sources spreadsheet, including source type, trustworthiness rating, topics, audience, and notes. That metadata is copied onto each chunk so it can support later review and retrieval filtering.

## Current limitations

- Cleaning removes whitespace issues and exact known boilerplate labels. It does not decide whether article claims or promotional text are appropriate for PawGo; that text may remain in the chunks.
- The current pipeline sends every chunk with source metadata to Qdrant. Source and chunk approval filtering has not been implemented, so review the content before using it in bot answers.
- Some websites block automated requests or return errors. A failed URL is skipped and will not appear in later output files.
- Ollama and Qdrant addresses are local-development settings in `embed.js` and `load-qdrant.js`. For a shared team or Salesforce-connected deployment, the services need to be hosted somewhere Salesforce can reach; teammates' `localhost` services are not shared.
